How it works

You set the limits

One config file says what the machine can take: seven sessions running stacks, five heavy test runs, one e2e run at a time. Change a number and it applies within two seconds.

Sessions take turns

A session holds a slot while its stack runs. Heavy commands run inside a test slot. When everything is taken, they wait in line and start the moment it's their turn.

Nothing stays stuck

Every slot belongs to a session and a process. If either dies, even with kill -9, the slot is free again at once. No one has to clean up by hand.

You see everything

Type slots for a live dashboard: what each session holds and runs, who's waiting, and a short list of what needs you, with a key to fix each.

The commands you'll use

# hold a test slot for one command; exits with the command's exit code
slots run test -- npx vitest run

# hold a slot across commands, while your stack runs
slots acquire agent --wait
slots release agent

# see who holds and waits for what
slots status
