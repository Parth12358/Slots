Many agents, one machine, no collisions.

slots coordinates the heavy work of many Claude Code sessions on a single computer. You declare what the machine can take. Sessions take turns at builds, test suites and dev stacks, in the order they asked, and a crashed session never leaves anything held.

How it works

One daemon per machine holds every lease, in one queue. Everything else is a client of it.

You set the limits

A config file says what the machine can take: seven sessions running stacks, five heavy test runs, one e2e run at a time. Change a number and it applies within two seconds.

Sessions take turns

A session holds an agent slot while its stack runs, and heavy commands run inside a test slot. When everything is taken, requests wait in arrival order and are told the moment it's their turn.

Leases end with their holder

Every slot belongs to a session and a process. If either exits, even with kill -9, the slot is free within seconds. If the daemon itself is killed, the next command restarts it with nothing lost.

The agents follow the rules

Claude Code hooks register each session and stop heavy commands that run without a slot, telling Claude exactly how to get one. Ending a session gives back everything it held.

Five commands

Most days, these are all anyone types. Agents use the same ones.

# run one heavy command in a test slot; exits with its exit code
slots run test -- npx vitest run

# hold an agent slot while your stack runs
slots acquire agent --wait
slots release agent

# see who holds and waits for what, or open the dashboard
slots status
slots
